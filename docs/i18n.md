# Internationalisation & multi-currency

Zero-dependency i18n for CH / EU / US. UI languages: **en, de, fr, it, es**.
Currencies: **CHF, EUR, USD, GBP** (any ISO 4217 code Intl knows also works).

## Why no library

Typed JSON dictionaries + a ~150-line ICU-lite formatter cover what we need
(interpolation, plurals, select) with compile-time key checking and no bundle
cost. `next-intl` would add routing/middleware we don't need (locale is a user
and tenant setting, not a URL segment). Revisit if we need ICU number/date
skeletons inside messages or URL-prefixed marketing pages.

## Locale resolution

`user preference → locale cookie → tenant default → Accept-Language → en`

- **User preference** — `profiles.locale`, counted only when
  `profiles.locale_set_at` is set (the column defaults to `'en'` for everyone).
- **Cookie** — `locale`, written by the language switcher (works signed out).
- **Tenant default** — `app_settings.default_locale`.
- If the tenant restricts languages (`settings.languages` /
  `app_settings.enabled_locales`), only those are offered and resolved.

Formatting uses the tenant's **country** to build the Intl tag (`de` + `CH` →
`de-CH`, `en` + `US` → `en-US`), the tenant **currency**, and the tenant
**time zone** (`app_settings.timezone`, default from country).

## Usage

```tsx
// Server component / action
import { getI18n } from "@/lib/i18n/server";
const { t, f } = await getI18n();
t("invoices.due", { date: f.date(inv.dueDate) });
f.money(inv.total);                         // tenant currency
t.dynamic(`status.${row.status}`, undefined, row.status); // runtime keys

// Client component
import { useT, useFormat } from "@/lib/i18n/client";
const t = useT(); const f = useFormat();

// Emails / PDFs / cron (no request)
import { getStandaloneI18n } from "@/lib/i18n/messages";
const { t, f } = getStandaloneI18n({ locale: profile.locale, country: org.country, currency: org.currency });

// Primitives
import { formatMoney, formatDate, firstDayOfWeek, dateOrder } from "@/lib/format";
formatMoney(1234.5, "CHF", "de-CH"); // CHF 1'234.50
formatMoney(1234.5, "EUR", "de-DE"); // 1.234,50 €
formatMoney(1234.5, "USD", "en-US"); // $1,234.50
```

Messages: `"{count, plural, =0 {No invoices} one {# invoice} other {# invoices}}"`.

## Adding / changing strings

1. Add the key to `src/messages/en.json` (source of truth).
2. Add it to `de.json`, `fr.json`, `it.json`, `es.json` — `tsc` fails until all have it.
3. Swiss German: use "ss", never "ß".
4. Run `npm run i18n:check` (missing/extra keys, placeholder parity, plural
   `other` branches, "ß", unknown `t("…")` keys in `src/`). `--strict` also
   fails on strings identical to English.
