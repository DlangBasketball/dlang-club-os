Deploying the
Club OS to production

A step-by-step path to a live, operational, fully responsive deployment of the DLang Basketball Club OS — from a zip on your disk to a real club running real registrations and payments.

App → Vercel DB / Auth / Storage → Supabase (EU · Frankfurt) Payments → Stripe Email → Resend

A live URL takes about an afternoon. Going fully operational with real money requires passing the deploy gate below first — don't skip it.

⛔ Deploy gate — do not take real payments until all four pass

  • Auth — every role (admin, parent, coach) logs in, session persists, password reset works, redirect URLs locked.
  • Payments — Stripe test cards (success / decline / 3DS) flow end-to-end; webhook verified & idempotent; manual payments immutable.
  • RLS — psql -f testing/rls_test_suite.sql prints zero FAIL.
  • Privacy — export & deletion are own-family-only; erasure is admin-only; consent records immutable.
0

Accounts & code

≈ 30 min · prerequisites

Vercel deploys from Git, and the zip has no repo yet — so the first real action is getting the code onto GitHub.

  1. Create the accounts you'll need

    GitHub, Vercel, Supabase (a paid tier — needed for point-in-time recovery), Stripe, and Resend.

  2. Push the app to a private GitHub repo

    Run from inside the dlang-club-os folder. The .gitignore already excludes .env and node_modules, so no secrets leak.

    terminal
    # from the dlang-club-os/ root
git init && git add . && git commit -m "Initial commit"
# create an empty PRIVATE repo on github.com, then:
git remote add origin git@github.com:YOURORG/dlang-club-os.git
git push -u origin main
1

Supabase backend

database · auth · storage

This is the data layer the 16 migrations target. Host it in an EU region for Swiss / FADP data residency.

  1. Create the project in Frankfurt (EU)

    Paid tier. Then copy the Project URL, anon key, and service_role key from Settings → API — you'll need them in Phase 3.

  2. Apply the 16 migrations, then the production seed

    Migrations must run in filename order; db push handles that. Run the seed exactly once.

    terminal · repo root
    supabase link --project-ref <PROJECT_REF>
supabase db push
psql "$SUPABASE_DB_URL" -v ON_ERROR_STOP=1 \
  -f supabase/seeds/seed_production.sql

    The seed creates the club org, settings, consent forms and one starter program — no demo families. Replace the consent body text with legally-reviewed wording before opening registration.

  3. Configure Auth

    Enable email confirmations, set a password policy, and turn on sign-in / sign-up rate limiting. Leave the Site & Redirect URLs for now — you'll fill them in Phase 4 once you have a domain.

2

Resend email

confirmations · reminders

DNS verification takes time to propagate, so start this early and let it bake while you deploy.

  1. Add & verify your sending domain

    e.g. mail.dlangbasketball.ch. Add the SPF, DKIM and DMARC records Resend gives you at your DNS host and wait for Verified.

  2. Create an API key

    You'll set it as RESEND_API_KEY and the sender as RESEND_FROM in Phase 3. note the variable is RESEND_FROM, not RESEND_FROM_EMAIL.

3

Deploy to Vercel

the app itself

  1. Import the GitHub repo

    Vercel auto-detects Next.js. Root = repo root, build = next build, install = npm install, Node 20.x.

  2. Add every environment variable

    Set them for Production and Preview (use Stripe/Resend test keys in Preview). The canonical list is the bundled .env.example.

    Vercel → Settings → Environment Variables
    NEXT_PUBLIC_SUPABASE_URL        # public
NEXT_PUBLIC_SUPABASE_ANON_KEY   # public
SUPABASE_SERVICE_ROLE_KEY       # SECRET — bypasses RLS, server only
NEXT_PUBLIC_SITE_URL            # your domain, no trailing slash
STRIPE_SECRET_KEY               # SECRET — sk_live_… (sk_test_ in Preview)
STRIPE_WEBHOOK_SECRET           # SECRET — set in Phase 4
RESEND_API_KEY                  # SECRET
RESEND_FROM                     # "DLang Basketball <noreply@…>"
CLUB_ADMIN_EMAIL                # new-registration alerts

    Critical: no secret may carry the NEXT_PUBLIC_ prefix — the app's assertServerEnv() refuses to boot if a secret is exposed publicly or a required one is missing.

  3. Deploy & add your custom domain

    Deploy main → Production. Add the custom domain; Vercel provisions SSL automatically. Smoke-test that /login loads with no console errors.

4

Wire the cross-references

the part people forget

⚠️ Chicken-and-egg

Three settings depend on the live domain you only got in Phase 3 — so they're done now, not earlier. Get all three pointing at the same URL.

  1. Set NEXT_PUBLIC_SITE_URL to your domain

    No trailing slash, then redeploy so it takes effect.

  2. Lock Supabase redirect URLs

    Auth → URL Configuration: Site URL = production domain; add your Vercel production + preview URLs to Redirect URLs (and nothing else).

  3. Add the Stripe webhook

    Developers → Webhooks → Add endpoint:

    endpoint URL
    https://<your-domain>/api/stripe/webhook

    Subscribe to at least checkout.session.completed. Copy the signing secret into STRIPE_WEBHOOK_SECRET. Use live keys for Production and a separate test webhook for Preview.

5

Bootstrap the first admin

no inviter exists yet

  1. Create the auth user

    Supabase → Authentication → Add user, with the admin's email and a password.

  2. Link the profile & grant the admin role

    Run in the Supabase SQL editor after the auth user exists:

    Supabase → SQL editor
    with org as (select id from public.organizations where slug='dlang'),
     p as (
       update public.profiles
          set org_id=(select id from org),
              full_name=coalesce(full_name,'Club Admin')
        where email='ADMIN_EMAIL_HERE'
        returning id, org_id
     )
insert into public.staff_roles (org_id, profile_id, role)
select p.org_id, p.id, 'admin' from p
on conflict do nothing;

    Then log in, finish onboarding, invite coach / finance staff, and publish the starter program from the UI.
